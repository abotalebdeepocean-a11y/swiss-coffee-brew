# ROVENTO Coffee

واجهة متجر ROVENTO مبنية باستخدام React وVite وTypeScript. **Supabase هو مصدر البيانات الأساسي** للمصادقة والكتالوج والطلبات وإعدادات المتجر. لا تضف تدفقات بيانات جديدة إلى أي backend آخر.

## المتطلبات

- Node.js 22+
- حساب Supabase ومشروع مُهيأ بالـ schema الحالي
- مفاتيح Supabase الخاصة بالواجهة

## التشغيل المحلي

1. انسخ `.env.example` إلى `.env`.
2. ضع عنوان مشروع Supabase ومفتاحه العام في:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. ثبّت الاعتماديات وشغّل التطبيق:

```bash
npm install
npm run dev
```

للتحقق من البناء:

```bash
npm run build
```

## قاعدة البيانات والطلبات

- ملف إعداد عميل Supabase: `src/lib/supabase.ts`
- المصادقة: `src/hooks/use-auth.ts`
- Migration الأساس: `supabase/migrations/20261015000000_supabase_foundation.sql`
- الطلبات تُنشأ من خلال RPC باسم `create_order`. السعر والإجمالي يُحسبان داخل قاعدة البيانات من سجل المنتج، ولا تُقبل الأسعار التي يرسلها المتصفح.
- الـ migration يحافظ على الأسعار الحالية، وحالة تفعيل المنتجات، وإعداد الشحن الموجودة في Supabase. لا تُطبّق تغييرات تجارية أو أسعار جديدة دون اعتمادها.
- طبّق migration على مشروع Supabase المقصود بعد مراجعة نسخة احتياطية، ثم اختبر إنشاء الطلبات وسياسات RLS في بيئة اختبار قبل الإنتاج.

## الأمان والإعدادات

- لا تضع `service_role` key أو أي secret في متغير يبدأ بـ `VITE_` أو في الواجهة الأمامية.
- استخدم فقط المفتاح العام (publishable/anon) في المتصفح، واعتمد على RLS وعمليات قاعدة البيانات للتحقق من الصلاحيات.
- تفعيل تسجيل الدخول المجهول وإعداد إرسال رموز البريد الإلكتروني يجب أن يتم من لوحة Supabase حسب سياسة المشروع.
- لا تُدمج التغييرات أو تنشرها إلى الإنتاج قبل نجاح البناء واختبار المصادقة والكتالوج والطلب على مشروع Supabase فعلي.
